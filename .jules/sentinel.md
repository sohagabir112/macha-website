## 2024-03-18 - Missing Authorization Checks in Server Actions (IDOR)
**Vulnerability:** Server actions for modifying user data (cart items) were only checking if the item ID existed and did not verify if the authenticated user owned the item being modified. This created an Insecure Direct Object Reference (IDOR) vulnerability where an unauthenticated or authenticated user could modify or delete other users' cart items simply by passing a valid `itemId`.
**Learning:** In Next.js Server Actions interacting with Supabase, relying solely on `itemId` for updates/deletes is insecure because Server Actions are essentially public API endpoints. Without Row Level Security (RLS) enforcement on the Supabase client or explicit user scoping in queries, the action has broad permissions.
**Prevention:** Always authenticate the user (`supabase.auth.getUser()`) at the beginning of sensitive server actions. When updating or deleting records, ALWAYS scope the query to the authenticated user's ID (e.g., `.eq('user_id', user.id)` in addition to the item ID) to ensure they can only modify their own resources.
