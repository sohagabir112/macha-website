## 2025-03-29 - Missing IDOR Protection in Server Actions
**Vulnerability:** Server actions (`updateCartItem`, `removeCartItem`) manipulated database records using only the object ID provided by the client, without verifying that the authenticated user owned the object. This allowed any user to modify or delete cart items belonging to other users (Insecure Direct Object Reference).
**Learning:** Even if a server action seems internal, any ID passed from the client must be treated as untrusted. Supabase Row Level Security (RLS) provides a safety net, but application-level queries must still explicitly scope operations to the authenticated user to prevent unauthorized access and logical errors.
**Prevention:** Always verify the user's authentication status within server actions that modify data (`const { data: { user } } = await supabase.auth.getUser()`). Append `.eq('user_id', user.id)` to all update and delete queries to ensure the operation is strictly scoped to the data owned by the authenticated user.
